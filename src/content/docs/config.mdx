Kickoutchi runs fine with no config file at all. When you want different defaults, add a small
TOML file. The repository ships a
[ready-to-copy example](https://github.com/nuggocto/kickoutchi/blob/shrek/config.example.toml) that
covers the settings and shows an exact label winning over a wildcard one.

## Location

By default Kickoutchi looks in your platform's config directory:

| Platform | Path                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| Linux    | `$XDG_CONFIG_HOME/kickoutchi/config.toml` (usually `~/.config/kickoutchi/config.toml`) |
| macOS    | `~/Library/Application Support/kickoutchi/config.toml`                                 |
| Windows  | `%APPDATA%\kickoutchi\config.toml`                                                     |

The global `--config FILE` flag points at another file. In the release after 1.7.1, on Linux and
macOS, a config file must be a regular file, a symlink to one, or `/dev/null` (an empty config). A
FIFO, or process substitution such as `--config <(...)`, then fails at once; in 1.7.1 a FIFO with no
writer stalls startup.

### Under sudo

`sudo` normally resets `HOME`, which would point Kickoutchi at root's config. On Linux and macOS,
`sudo kick` looks in the home directory of the user who ran sudo first, so your protected names,
labels, and confirmation settings still apply. Root reads that file only if it's a regular file
owned by that user; anything else there, such as a symlink to another user's file, is an error. If
that user has no file, root's default path is used. Your own `XDG_CONFIG_HOME` isn't visible under
sudo, so pass a file kept there with `--config`.

<Callout type="note" title="Missing files: two rules">
  No file at the default path just means "use the built-in defaults", which is the normal first-run
  state. A file you name with `--config` must exist, though. If it's missing, that's an error,
  because you asked for that exact file.
</Callout>

## Precedence

Settings come in layers, like any self-respecting swamp: built-in defaults at the bottom, then the
config file, then CLI flags on top. Most keys replace their default; `protected_processes` adds to
it (see below).

## Keys

Every key is optional. Anything you leave out keeps its default.

| Key                        | Type             | Default       | Meaning                                                                                                  |
| -------------------------- | ---------------- | ------------- | -------------------------------------------------------------------------------------------------------- |
| `refresh_interval_seconds` | integer (1–3600) | `3`           | How often the TUI collects ports again.                                                                  |
| `default_sort`             | string           | `"port"`      | Default sort for the CLI and TUI. One of `port`, `pid`, `protocol`, `process`, `parent`, `scope`.        |
| `hide_system_processes`    | boolean          | `false`       | Hide rows Kickoutchi classifies, conservatively, as system or service processes.                         |
| `confirm_force_kill`       | boolean          | `true`        | Make force kills ask you to type `force` (unless you pass `--yes`).                                      |
| `docker_enrichment`        | boolean          | _(ignored)_   | Old key, kept so older files load. `true` and `false` are accepted; Docker details were removed.         |
| `check_for_updates`        | boolean          | _(ignored)_   | Old key, kept so older files load. `true` and `false` are accepted; Kickoutchi never checks for updates. |
| `protected_processes`      | string[]         | _(see below)_ | Extra process names that need stronger confirmation. Added to the built-in list.                         |
| `[[ports]]`                | table array      | _(none)_      | Endpoint labels, up to 256. See [below](#endpoint-labels).                                               |

Config files can be up to 64 KiB. A larger file is rejected outright, never partly parsed.

### Example

<CommandBlock
  lang="toml"
  label="~/.config/kickoutchi/config.toml"
  code={`refresh_interval_seconds = 5
default_sort = "scope"
hide_system_processes = true
confirm_force_kill = true
protected_processes = ["redis", "mysqld"]

[[ports]]
protocol = "tcp"
address = "127.0.0.1"
port = 3000
label = "web dev"`}
/>

<Callout type="warning" title="Typos won't pass silently">
  Kickoutchi rejects unknown keys instead of ignoring them. A misspelled key like
  `refresh_intreval_seconds` fails to load, and the error names it. The same goes for out-of-range
  or mistyped values, such as a bad `default_sort`. A broken file is a hard error (exit `1`), not a
  quiet fallback that hides your mistake.
</Callout>

## Endpoint labels

`5432` is a port number. `postgres` is a name you'll recognize at 2am. Each `[[ports]]` block gives
one endpoint a label that then shows up in the CLI table, wide enough TUI tables, plain search,
filters, `list --json`, snapshots, watch events, and `why` output.

<CommandBlock
  lang="toml"
  label="endpoint labels"
  code={`[[ports]]
protocol = "tcp"
address = "127.0.0.1"
port = 3000
label = "web dev"

[[ports]]
protocol = "tcp"
address = "\*"
port = 3000
label = "web service"

[[ports]]
protocol = "udp"
address = "fe80::1"
scope_id = 3
port = 5353
label = "mDNS"`}
/>

| Field      | Required | Meaning                                                              |
| ---------- | -------- | -------------------------------------------------------------------- |
| `protocol` | yes      | `"tcp"` or `"udp"`. The two are matched separately.                  |
| `address`  | yes      | An exact literal IPv4/IPv6 address, or `"*"` for any address.        |
| `port`     | yes      | The exact port.                                                      |
| `scope_id` | no       | Nonzero IPv6 interface index. Valid only with an exact IPv6 address. |
| `label`    | yes      | The display text.                                                    |

Matching rules:

- Exact beats wildcard. With both TCP blocks above, `127.0.0.1:3000` shows `web dev`, and any other
  address on TCP 3000 shows `web service`.
- IPv4-mapped IPv6 addresses count as IPv4, both for matching and for spotting duplicates.
- Hostnames, DNS names, CIDR ranges, interface names, and `%zone` syntax are rejected. Use
  `scope_id` for an IPv6 scope.
- Duplicate selectors are an error, so there's no "last one wins" surprise.

<Callout type="note" title="Labels are checked, not just stored">
  A label must be nonempty, visible Unicode of at most 128 UTF-8 bytes. Kickoutchi rejects control
  characters, terminal escapes, bidi controls, and zero-width text, so a config file can't sneak
  terminal control sequences into your port table. Tables clip labels to 32 terminal columns;
  structured output keeps the full label.
</Callout>

## Protected processes

`protected_processes` adds your names on top of the built-in safety list, never instead of it.
Adding `redis` can't strip protection from `systemd` or `postgres`.

Matching is exact and never a substring, so `postgres-backup-helper` doesn't inherit `postgres`'s
protection. It's case-sensitive on Linux and macOS and case-insensitive on Windows. On Linux, a
protected name longer than 15 bytes also matches the kernel's truncated `/proc/<pid>/comm` name
when that's the only name available.

The built-in list covers processes whose accidental termination takes down your containers,
database, init system, or desktop:

```text
docker, docker.exe, dockerd, dockerd.exe, docker-proxy, docker-proxy.exe,
Docker Desktop.exe, com.docker.backend, com.docker.backend.exe, postgres,
postgres.exe, systemd, System, smss.exe, csrss.exe, wininit.exe, services.exe,
lsass.exe, svchost.exe, winlogon.exe, explorer.exe, dwm.exe, WindowServer
```

The merged list holds at most 256 names and rejects empty ones. See [Safety](/docs/safety) for the
checks protected processes get at kill time.

## Hiding system processes

With `hide_system_processes = true`, the default view drops rows Kickoutchi is confident are system
or service processes: PID 0 and 1, direct children of PID 1, and a short list of well-known OS
process names (plus PIDs up to 4 and children of `services.exe` on Windows). A row whose owner is
hidden has no PID to classify, so it stays visible, and the option hides more under `sudo`. The
rule is deliberately cautious. A protected app like `postgres` isn't treated as a system process
just because it's protected; those are separate ideas.
