Run either binary with no subcommand to open the terminal UI.

<CommandBlock code={"kickoutchi\nkick"} label="open the TUI" />

Both names run the same program. `kickoutchi` is the full name and `kick` the short one.

## The layout

The screen has four parts, top to bottom:

- The header shows the title and a one-line key hint:
  `r refresh / search s sort x/X kill t/T tree ? help q quit` on Linux and macOS, without the
  tree keys on Windows.
- The Open Ports table has one row per socket, with `>>` marking the selected row.
- The details panel shows live context for the selected row.
- The status line shows visible and total port counts, how long ago the table refreshed, the sort,
  the filter, and the result of your last kill.

### Table columns

| Column    | What it shows                                                    |
| --------- | ---------------------------------------------------------------- |
| `PROTO`   | `TCP` (listening) or `UDP` (bound)                               |
| `ADDRESS` | The bound local address                                          |
| `PORT`    | The local port                                                   |
| `PID`     | Owning process ID, or `-` when the OS won't say                  |
| `PROCESS` | Process name, or `-` when the OS won't say                       |
| `STATE`   | `LISTEN` or `BOUND`                                              |
| `SCOPE`   | `public`, `local`, or `loopback`                                 |
| `LABEL`   | Your configured endpoint label, when the terminal is wide enough |

<Callout type="note" title="Reading IPv4 and IPv6 rows">
  `127.0.0.1` and `::1` are loopback addresses. `0.0.0.0` and `::` listen on every interface. An
  address starting with `fe80::` is IPv6 link-local. A suffix such as `%3` names an interface;
  Linux and macOS can't report it, so their IPv6 rows show the plain address.

`public` means a wildcard bind, not that the Internet can reach it. `local` is a concrete
non-loopback address, and `loopback` stays on this machine. A `-` under `PID` or `PROCESS` means
Kickoutchi couldn't read the owner, not that there is none.

</Callout>

Row styles tell you what you can act on:

- Bold rows have an owner Kickoutchi could read, usually one of your own processes.
- Plain rows have a hidden owner. The socket is visible, but the process holding it belongs to
  someone Kickoutchi can't read, usually another user. `sudo kick` shows these owners.
- Yellow rows have a known PID with some details unreadable.
- Red rows are protected processes. Killing one asks you to type its PID or name.

The colors come from your terminal's palette, so the table follows your theme. Set `NO_COLOR` to
drop them; bold and reverse video stay. The help modal (`?`) repeats this legend.

## Moving around

| Key             | Action                                      |
| --------------- | ------------------------------------------- |
| `j` / `↓`       | Move selection down                         |
| `k` / `↑`       | Move selection up                           |
| `Enter`         | Open the details modal for the selected row |
| `?`             | Open the help modal                         |
| `m`             | Open the full kill results and errors       |
| `q` or `Ctrl+C` | Quit                                        |

## Search and filter

Press `/` and type. The table narrows with every key.

- `Enter` keeps the filter and returns to the table.
- `Esc` clears it.

Plain text matches the port, address, PID, process, path, command line, parent, and label. The
structured filters from the CLI work here too:

<CommandBlock
  code={
    "port:3000   proto:udp   scope:public   protected:true   parent:node\nlabel:web   address:127.0.0.1   scope_id:3   family:ipv6"
  }
  lang="text"
  label="filter syntax"
/>

Every term must match, and `address:` compares parsed addresses, not text. `state:` belongs to
`kick watch`; here it's an error, not a plain search word. The
[command reference](/docs/commands#filters) has the full grammar.

## Sorting

Press `s` to cycle the sort: port, pid, protocol, process, parent, scope, and back to port. Sorting
by `scope` puts `public` binds first, which are the ones worth a second look.

## Refreshing

Kickoutchi collects ports again every 3 seconds by default; change it with
`refresh_interval_seconds` in your [config](/docs/config). Press `r` to refresh now. The status
line shows how long ago the last refresh was.

## Details

The details panel follows the selected row. Press `Enter` for the full details modal, which also
loads the owner's UID, the process's children, and any protected-process warnings. The UID and
children show only when they came from the same process as the row, so a reused PID never mixes
two processes in one view. When the owner belongs to another user, the panel says so and suggests
`sudo`.

## Kicking a process out

| Key               | Action                                             |
| ----------------- | -------------------------------------------------- |
| `x`               | Terminate the selected process                     |
| `X` (`Shift`+`x`) | Force-kill the selected process                    |
| `t`               | Terminate the selected process tree (Linux/macOS)  |
| `T` (`Shift`+`t`) | Force-kill the selected process tree (Linux/macOS) |

`x` and `X` open the Confirm Termination modal. It shows the target, the affected ports, and the
equivalent shell command, such as `kill 18422`, or `kill -9 18422` for a force kill.

`t` and `T` open Confirm Tree Termination instead. Kickoutchi lists the tree in the background,
shows how many processes it holds with a preview, and asks you to type `tree` (or `force` for `T`).
When you confirm, it scans the tree again from scratch before freezing anything.

<Callout type="safety" title="What you type depends on the target">
  - Normal kill: type `y`.
  - Force kill: type `force`, unless you turned that off in your config.
  - Tree kill: type `tree`. A force tree kill still takes `force`.
  - Protected process: type its PID or its process name. The name is offered only when it can be
    typed exactly as shown; the PID always works. You can't skip this step.

`Esc` cancels. Kickoutchi checks the target again right before signalling, so it only ever hits
the process you confirmed.

</Callout>

After a kill, the status area reports the outcome, and the next refresh shows the port gone. Kill
results and errors get their own wrapped rows above the status line. When a report doesn't fit,
such as a cleanup failure that lists many stopped PIDs, the preview says so and `m` opens the full
report.

The TUI offers tree kills only. For a process group, use the CLI's `--group`, which shows the
whole group in a banner before you confirm.

## Edge cases

- `Esc` depends on what's on screen. It clears the search, closes a modal, cancels a kill
  confirmation, or quits.
- Starting in 1.7.2, closing the terminal window on Linux and macOS ends the TUI.
  See [Troubleshooting](/docs/troubleshooting#the-tui-kept-running-after-i-closed-its-terminal)
  for older versions.
  A kill in progress finishes its cleanup before the TUI exits. A TUI started with `SIGHUP`
  ignored, for example under `nohup`, can still linger. `SIGTERM`, as sent at shutdown, restores
  the terminal before Kickoutchi exits.
- Below 80×20 the TUI shows "Terminal too small" instead of a cramped table. Resize and it comes
  back.
- A kill confirmation wraps its warnings instead of cutting them off. If the terminal can't fit
  every warning and the prompt, Kickoutchi cancels the confirmation rather than show part of it.
