`why` takes one snapshot and then tries a quick bind. `watch` compares snapshots over time. Neither
sends signals.

## `why`: the real reason a bind fails

`Address already in use` has at least four different causes. `why` tells them apart by taking one
snapshot, then trying the exact bind and releasing it at once.

<Terminal
  title="kick why 3000"
  lines={[
    { kind: "command", text: "kick why 3000" },
    { kind: "output", text: "TCP 127.0.0.1:3000  in use by PID 18422 (node)  [web dev]" },
    { kind: "output", text: "TCP [::1]:3000      free" },
    { kind: "command", text: "kick why 3000 --verbose" },
    { kind: "muted", text: "WHY port=3000 protocols=TCP addresses=127.0.0.1,::1 snapshot=partial" },
    { kind: "output", text: "tcp://127.0.0.1:3000 verdict=owned certainty=proven label=web dev" },
    { kind: "output", text: "  probe=address_in_use raw_os_error=98" },
    { kind: "output", text: "  evidence code=visible_verified_owner source=linux_procfs" },
    { kind: "muted", text: "    PID 18422 (node) owned the endpoint at snapshot capture" },
    { kind: "output", text: "  evidence code=exact_bind_address_in_use source=bind_probe" },
    { kind: "muted", text: "    the exact bind probe reported that the address is in use" },
    { kind: "output", text: "tcp://[::1]:3000 verdict=bindable_now certainty=proven label=-" },
    { kind: "output", text: "  evidence code=exact_bind_succeeded source=bind_probe" },
    { kind: "output", text: "aggregate_exit_code=3" },
  ]}
/>

Look at the two rows: `127.0.0.1:3000` is taken and `[::1]:3000` is free. A tool that just says
"port 3000 is busy" hides that. By default you get one line per endpoint. `--verbose` adds the probe
result, evidence, and gaps behind each verdict, and `--json` prints the same facts as one
`kickoutchi.why/1` document.

### Which endpoints get probed

By default `why` probes TCP on `127.0.0.1`, then `::1`, the two addresses a local dev server
usually means. Widen it with flags:

<CommandBlock
  code={
    "kick why 3000\nkick why 5353 --udp --address 127.0.0.1\nkick why 3000 --tcp --address :: --ipv6-only\nkick why 3000 --all-protocols --all-addresses --json"
  }
  label="why examples"
/>

- `--tcp`, `--udp`, and `--all-protocols` pick the protocols. TCP comes before UDP.
- `--address ADDR` probes one literal local IP. `%zone` syntax isn't accepted; use `--scope-id`.
- `--all-addresses` probes `127.0.0.1`, `0.0.0.0`, `::1`, then `::`. It doesn't list your
  interfaces.
- `--scope-id ID` takes a nonzero IPv6 interface index and needs one explicit IPv6 `--address`.
- `--ipv6-only` and `--dual-stack` can't be combined, and work only when every address is IPv6.
  With neither, you get the OS default.
- `--reuse-address` probes with address reuse turned on.

`why` goes protocol by protocol and probes at most eight endpoints.

### Verdicts and certainty

Every endpoint gets a verdict and a `certainty` that applies to that claim alone:

| Certainty   | Means                                                     |
| ----------- | --------------------------------------------------------- |
| `proven`    | Seen directly: a probe result or a verified owner.        |
| `estimated` | Calculated, for example from a Linux TCP timer.           |
| `heuristic` | Inferred from a pattern rather than a fact.               |
| `unknown`   | Not established, usually because of scope or permissions. |

The verdicts tell apart bindable, in use, permission denied, address unavailable, unsupported, and
other OS errors. Each one carries ordered `evidence` lines and, where
something couldn't be established, `gap` lines naming what's missing.

An endpoint in use is `owned` when a verified process holds it, and `owner_hidden` when the holder
can't be seen, typically another user's daemon your account can't read. On Linux the
evidence then names the UID that created the socket, for example `uid 970 created the socket`.
`kernel_state_observed` is reserved for sockets no process holds after every process was read,
and for TCP states such as `TIME_WAIT`.

<Callout type="warning" title="A successful probe is not a reservation">
  `verdict=bindable_now` means the exact bind worked and was released at once. It's a fact about one
  instant. Another process can take the endpoint a millisecond later, and `why` doesn't claim
  otherwise.
</Callout>

### Exit codes

`why` uses the shared [exit codes](/docs/commands#exit-codes), with one extra rule: when it probes
several endpoints, the exit code is the worst result, in the order `1`, `4`, `3`. It's `0` only when
every endpoint proved bindable.

## `watch`: ports changing hands

`watch` takes snapshots on an interval and prints an event whenever something changes.

<Terminal
  title="kick watch --tcp --port 3000"
  lines={[
    { kind: "command", text: "kick watch --tcp --port 3000" },
    {
      kind: "output",
      text: "BIND TCP 127.0.0.1:3000 listen owners=18422 label=web dev filter=matched certainty=proven",
    },
    {
      kind: "output",
      text: "RELEASE TCP 127.0.0.1:3000 listen owners=18422 label=web dev filter=matched certainty=proven",
    },
  ]}
/>

<CommandBlock
  code={
    "kick watch\nkick watch --tcp --address 127.0.0.1 --port 3000\nkick watch --filter label:web --interval 500ms\nkick watch --filter state:established --duration 30s --json"
  }
  label="watch examples"
/>

### Events

| Event            | Emitted when                                                          |
| ---------------- | --------------------------------------------------------------------- |
| `baseline`       | The first valid snapshot, describing what was already open.           |
| `bind`           | An endpoint appeared.                                                 |
| `release`        | An endpoint disappeared.                                              |
| `replacement`    | The same endpoint is now held by a different owner identity.          |
| `collection_gap` | A poll failed. The last valid snapshot is kept rather than discarded. |

`replacement` exists because a PID alone doesn't identify a process. Kickoutchi compares the PID
and its start time, so a recycled PID on the same port shows up as a replacement instead of looking
like nothing happened.

### Timing

- `--interval` accepts `100ms..=60s`; the default is `1s`.
- `--duration` accepts `100ms..=7d`. Without it, `watch` runs until Ctrl-C.
- Polls never overlap. If collection is slower than your interval, the next poll waits rather than
  building a backlog.

<Callout type="note" title="Polling, not a kernel event feed">
  A socket that opens and closes between two polls is never seen, several changes can collapse into
  one net difference, and the times bracket a collection attempt, not the exact moment of the
  change. A shorter `--interval` narrows that window but can't close it.
</Callout>

### Failure and recovery

A collection can fail now and then. `watch` says so instead of inventing events:

- If the first collection fails, it prints nothing and exits `1`.
- After a good baseline, a failed poll prints `collection_gap`, keeps the last good snapshot, and
  retries. It compares the next snapshot against that one, so a passing failure can't turn into a
  wave of false `release` events.
- The third failure in a row prints its gap and exits `1`.
- Collection gaps ignore your filters, so you always learn when watch stopped seeing.

Ctrl-C, the end of `--duration`, and a closed stdout (`kick watch --json | head`) all exit
successfully.

### Filtering

`watch` accepts the shared [filter grammar](/docs/commands#filters) plus a watch-only `state:`
field covering every native TCP state:

<CommandBlock
  code={
    "listen bound closed syn_sent syn_received established fin_wait1 fin_wait2\nclose_wait closing last_ack time_wait delete_tcb new_syn_received unknown"
  }
  lang="text"
  label="state: values"
/>

When a filter depends on something Kickoutchi couldn't read, such as an owner PID or a process
name, watch prints the event with `filter=indeterminate` instead of dropping it. A definite
non-match is still hidden. That way you know when a filter might have hidden something.

On a normal desktop this makes a narrow filter noisy: following one PID can also print every socket
whose owner you can't read. Add `--matched-only` to keep only definite matches, at the cost of
missing a match behind a permission boundary. Collection gaps always print.

<CommandBlock code={"kick watch --filter pid:18422 --matched-only"} label="definite matches only" />
