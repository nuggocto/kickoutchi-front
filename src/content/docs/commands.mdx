Use this page when you know the command and need its exact syntax. For worked examples, see the
[CLI walkthrough](/docs/cli) and [Scoped kills](/docs/scoped-kills).

## Binary names

| Binary       | Use                                                         |
| ------------ | ----------------------------------------------------------- |
| `kickoutchi` | Canonical name. Matches the crate, the docs, and this site. |
| `kick`       | Short alias for daily use. Same program.                    |

Running either with no subcommand opens the TUI. `--version` reports `kickoutchi` under both names.

## Global options

These work with or without a subcommand.

| Option                       | Description                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------- |
| `--config FILE`              | Read this config file instead of the platform default.                                       |
| `--refresh-interval SECONDS` | Override the configured refresh interval (1–3600). Out of range is a usage error (exit `2`). |
| `-v`, `--verbose`            | Show every probe result, evidence item, and gap in `why` output.                             |

## `list`

Print open ports and exit.

<CommandBlock code={"kick list [OPTIONS]"} lang="text" label="usage" />

| Option            | Description                                                                 |
| ----------------- | --------------------------------------------------------------------------- |
| `--port PORT`     | Only rows bound to this exact port.                                         |
| `--process TEXT`  | Only rows whose process name contains the text.                             |
| `--filter TEXT`   | TUI-style search text or structured filters (below).                        |
| `--sort MODE`     | Sort order (below). Defaults to your config's `default_sort`.               |
| `--json`          | Print the legacy visible-row `kickoutchi.list/1` array.                     |
| `--snapshot-json` | Print the complete, unfiltered `kickoutchi.snapshot/1` observation instead. |

An empty unfiltered list exits `0`. An empty filtered result exits `3`.

`--snapshot-json` can't be combined with `--port`, `--process`, `--filter`, or `--sort`; it ignores
`hide_system_processes` and leaves out full command lines. See
[Structured output](/docs/structured-output).

## `kill`

Terminate the process owning a port or PID, after confirmation.

<CommandBlock
  code={"kick kill <--pid PID[,PID...] | --port PORT[,PORT...]> [OPTIONS]"}
  lang="text"
  label="usage"
/>

Pass PIDs or ports, not both. Repeat the flag or separate values with commas to kill up to 128
processes behind one confirmation and one summary. `--tree` and `--group` take one target.

| Option        | Description                                                                                                |
| ------------- | ---------------------------------------------------------------------------------------------------------- |
| `--pid PID`   | Terminate a specific PID. Repeatable, or comma-separated.                                                  |
| `--port PORT` | Terminate the process that owns this port. Refuses ambiguous ports. Repeatable, or comma-separated.        |
| `--force`     | Ask for the `force` confirmation. Unix sends `kill -9`; every Windows kill is a hard termination anyway.   |
| `--yes`       | Skip the prompt. Never skips protected-process confirmation or the fresh checks before a scoped kill.      |
| `--tree`      | Terminate the target's whole descendant tree. Conflicts with `--group`.                                    |
| `--group`     | Linux/macOS only: terminate every visible member of the target's POSIX process group. Conflicts with tree. |

The equivalent command shown before confirmation is `kill PID` (terminate) or `kill -9 PID` (force)
on Linux/macOS, and `taskkill /F /PID PID` on Windows.

After delivery, `kill` waits up to two seconds and reports separately whether each process exited
and whether its confirmed ports are still visible. A batch's exit code is the most serious outcome
across its targets: `1`, then `4`, then `6`, then `3`.

Scoped kills ask you to type `tree`, `group`, or `force`. Kickoutchi collects the tree or group
again when you confirm and never acts on the preview. Windows rejects `--group`, and its `--tree`
contains the tree in a Job Object and terminates it outright.

## `inspect`

Show a process family without signalling anything.

<CommandBlock code={"kick inspect <--pid PID | --port PORT>"} lang="text" label="usage" />

Exactly one of `--pid` / `--port` is required.

| Option        | Description                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------- |
| `--pid PID`   | Show this PID's ancestors, descendants, siblings, ports, and process group where supported. |
| `--port PORT` | Show the family of the process that owns this port. Refuses ambiguity.                      |

`inspect --pid` is read-only and can inspect a portless supervisor. `inspect --port` follows the
same target-resolution rules as `kill --port`.

## `watch`

Stream socket changes until you stop it or the duration runs out. Read-only.

<CommandBlock code={"kick watch [OPTIONS]"} lang="text" label="usage" />

| Option              | Description                                                                   |
| ------------------- | ----------------------------------------------------------------------------- |
| `--tcp` / `--udp`   | Protocol selection. Neither flag means both; `--tcp --udp` also means both.   |
| `--address ADDRESS` | Match this literal normalized IP address across IPv6 scopes.                  |
| `--scope-id ID`     | Narrow an explicit IPv6 address to this nonzero interface index.              |
| `--port PORT`       | Match this exact nonzero port.                                                |
| `--filter TEXT`     | Plain or structured full-state filters, including watch-only `state:`.        |
| `--interval DUR`    | Poll every `100ms..=60s`. Default `1s`.                                       |
| `--duration DUR`    | Stop after `100ms..=7d` instead of waiting for Ctrl-C.                        |
| `--json`            | Emit `kickoutchi.watch_event/1` NDJSON to stdout; diagnostics stay on stderr. |
| `--matched-only`    | Emit only definite matches; drop events whose match is `indeterminate`.       |

Events are `baseline`, `bind`, `release`, `replacement`, and `collection_gap`. A failed first
collection exits `1`; after a good baseline, the third failure in a row exits `1`. Ctrl-C, the end
of `--duration`, and a closed stdout exit `0`. Watch never runs external programs while polling.

## `why`

Tell whether exact local endpoints can be bound right now. Read-only, apart from a brief bind that
it releases at once.

<CommandBlock code={"kick why <PORT> [OPTIONS]"} lang="text" label="usage" />

| Option              | Description                                                              |
| ------------------- | ------------------------------------------------------------------------ |
| `--tcp`             | TCP only (the default), ordered before UDP in a matrix.                  |
| `--udp`             | UDP endpoints only.                                                      |
| `--all-protocols`   | TCP then UDP.                                                            |
| `--address ADDRESS` | One literal local IP. No `%zone` syntax; use `--scope-id`.               |
| `--all-addresses`   | `127.0.0.1`, `0.0.0.0`, `::1`, then `::`. Does not enumerate interfaces. |
| `--scope-id ID`     | Nonzero IPv6 interface index; requires one explicit IPv6 `--address`.    |
| `--ipv6-only`       | Bind IPv6-only. Valid only when every address is IPv6.                   |
| `--dual-stack`      | Bind dual-stack. Can't be combined with `--ipv6-only`.                   |
| `--reuse-address`   | Enable address reuse for the diagnostic bind.                            |
| `--json`            | Print one `kickoutchi.why/1` document instead of human evidence.         |

Human output is one line per endpoint, such as `TCP 127.0.0.1:3000  in use by PID 18422 (node)`.
Add the global `--verbose` flag for the full evidence.

By default `why` probes TCP on `127.0.0.1`, then `::1`. It goes protocol by protocol and probes at
most eight endpoints. With several endpoints, the exit code is the worst result, in the order `1`,
`4`, `3`; it's `0` only when every endpoint proved bindable. See
[Watch & Why](/docs/watch-and-why).

## Filters

`list --filter`, `watch --filter`, and the TUI search box share this syntax. Every term must match,
including repeated fields. A bare word matches as a substring of any visible field.

| Filter                                            | Matches                                        |
| ------------------------------------------------- | ---------------------------------------------- |
| `pid:18422`                                       | Exact PID                                      |
| `port:3000`                                       | Exact port                                     |
| `proto:tcp` / `proto:udp`                         | Protocol                                       |
| `scope:public` / `scope:local` / `scope:loopback` | Bind scope                                     |
| `protected:true` / `protected:false`              | Protected status                               |
| `parent:node`                                     | Parent process name or PID (substring)         |
| `label:web`                                       | Configured endpoint label                      |
| `address:127.0.0.1`                               | Parsed, normalized IP address, not a substring |
| `scope_id:3`                                      | Numeric IPv6 interface scope                   |
| `family:ipv4` / `family:ipv6`                     | Normalized address family                      |
| `state:established`                               | Socket state (`watch` only)                    |

<CommandBlock
  code={
    "kick list --filter 3000\nkick list --filter port:3000\nkick list --filter 'label:web family:ipv4'\nkick list --filter address:127.0.0.1\nkick list --filter 'proto:tcp family:ipv6 parent:node'\nkick watch --filter state:listen"
  }
  label="filter examples"
/>

`address:` matching parses the address rather than comparing text, so `address:::1` and
`address:0:0:0:0:0:0:0:1` are the same query, and IPv4-mapped IPv6 addresses normalize to IPv4.

`state:` is reserved for `watch`. `list` and the TUI reject it instead of quietly treating it as
search text. Accepted values:

<CommandBlock
  code={
    "listen bound closed syn_sent syn_received established fin_wait1 fin_wait2\nclose_wait closing last_ack time_wait delete_tcb new_syn_received unknown"
  }
  lang="text"
  label="state: values"
/>

A filter expression can be up to 256 UTF-8 bytes. An invalid structured value, such as
`port:not-a-port`, is a usage error (exit `2`).

In `watch`, owner terms must all hold for the same owner; two different owners can't each satisfy
half of the expression. When a needed owner or metadata fact is missing, watch prints the event as
`indeterminate` instead of dropping it, unless you pass `--matched-only`.

## Sort modes

`port`, `pid`, `protocol`, `process`, `parent`, `scope`

Sorting by `scope` lists `public` binds first, then `local`, then `loopback`. Rows missing the sort
key sink to the bottom. In the TUI, `s` cycles through these in order.

## JSON output

`list --json` emits an array of objects with this stable shape:

| Field                 | Type                                  |
| --------------------- | ------------------------------------- |
| `protocol`            | `"tcp"` \| `"udp"`                    |
| `local_addr`          | string                                |
| `local_port`          | number                                |
| `state`               | `"listen"` \| `"bound"`               |
| `pid`                 | number \| `null`                      |
| `process_name`        | string \| `null`                      |
| `executable_path`     | string \| `null`                      |
| `command_line`        | string \| `null`                      |
| `parent_pid`          | number \| `null`                      |
| `parent_process_name` | string \| `null`                      |
| `child_pids`          | number[], always `[]`                 |
| `protected`           | boolean                               |
| `platform`            | `"linux"` \| `"macos"` \| `"windows"` |
| `permission`          | `"full"` \| `"partial"`               |
| `label`               | string \| `null`                      |

Missing metadata is `null`. An empty result is `[]`. `label`, added in 1.3.0, is the only field
ever added to this format. `child_pids` stays only for `1.x` compatibility and has no data behind it.

The other three formats, `kickoutchi.snapshot/1`, `kickoutchi.watch_event/1`, and
`kickoutchi.why/1`, are covered in [Structured output](/docs/structured-output).

## Exit codes

Scripts can rely on these numbers; they don't change.

| Code | Meaning                                                      |
| ---- | ------------------------------------------------------------ |
| `0`  | Command completed and its requested positive condition holds |
| `1`  | Operational or internal failure                              |
| `2`  | Invalid arguments                                            |
| `3`  | No match, or a requested endpoint is unavailable             |
| `4`  | Permissions prevented a reliable answer                      |
| `5`  | You cancelled the kill                                       |
| `6`  | Protected process needs confirmation                         |

## Config

Defaults for sort, refresh interval, protected processes, and endpoint labels live in a config
file. See [Configuration](/docs/config).
